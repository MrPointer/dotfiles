# Planning Grounding

`plan` grounds repository reality before it designs. Cheap delegated exploration
may collect evidence, but the coordinator normalizes and verifies material claims.
`grounding-notes.md` is an attributed repository-evidence store: Sources,
Observations, bounded Inferences, Relevance, and Unknowns. It records no design
recommendations. `research.md` is tracked but non-normative thematic working space
for verified evidence, real alternatives, working decisions, consequences, and
open design questions. Every decision needed later is restated in `plan.md`.

Ask one adaptive consequential technical question per human turn. Routine detail
is planner-owned. Surface repository evidence that contradicts Feature Definition
intent. Planning may directly correct only non-semantic factual metadata or an
unambiguous transcription error. Any correction affecting intent, scope,
requirements, acceptance evidence, constraints, dependencies, decision context,
or open questions changes `spec.md` to Draft, invalidates downstream gates, and
returns control to `clarify`; planning resumes only after Ready.
